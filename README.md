# DRP BuildLab — site

Static marketing site. No build step on deploy: Netlify publishes the
repository root as-is.

## Layout

```
src/                    the four pages, in Dutch — EDIT THESE
  index.html
  over-ons/index.html
  prijzen/index.html
  contact/index.html

be/  nl/  fr/  …            GENERATED, one directory per market — do not edit
                        17 of them: be nl fr lu ch de at es gb ie us ca mx id jp sg au

assets/                 css, js, translations, images
  styles.css
  app.js                UI behaviour and language application
  locale.js             market resolution and currency conversion
  i18n.js               all 7 languages
  markets.js            the market table — market -> language + currency
  icons/                favicon.svg, icon-192, icon-512
  img/

netlify/edge-functions/
  rates.js              /api/rates — EUR rates, cached an hour
  geo.js                /api/geo — country lookup (no longer used by the page)

tools/
  build-locales.js      regenerates the market directories + sitemap
  translate.js          drafts machine translations via DeepL
  serve.py              local preview server
  TESTING.md            how to test the localisation

404.html                served directly, not generated
_headers                cache and security headers
_redirects              market routing, geo root redirect, legacy URLs
netlify.toml            publish directory only
robots.txt              must live at the web root
sitemap.xml             generated by build-locales.js
site.webmanifest
favicon.ico             stays at root — browsers probe this path
apple-touch-icon.png    stays at root — iOS convention
```

## The one rule

**Edit `src/`, never a market directory.** The 17 market
directories are output. Anything you change in `gb/` is gone the next time
the generator runs:

```powershell
node tools/build-locales.js
```

Run that after editing any page in `src/`, or after adding a market to
`assets/markets.js`. It rewrites all 68 pages and
regenerates `sitemap.xml`.

The generated output is committed rather than built on Netlify. A build
command is one more thing that can fail on deploy — this site has already
lost an afternoon to a `netlify.toml` change — and generated files in git
show up in a diff.

## Markets

A market is a URL segment carrying **both** a language and a currency, the
way nike.com/gb/ and nike.com/mx/ do. That separation is the point: `/gb/`
and `/us/` are both English at different currencies, `/es/` and `/mx/`
both Spanish at different currencies.

17 markets, 7 languages, 10 currencies. Defined once in
`assets/markets.js` and read by both the page and the generator.

Adding one is a line in that file plus a rerun of the generator, then a
`Country` rule in `_redirects` so a bare `/` from that country lands there.

## Local preview

```powershell
python tools/serve.py           # http://127.0.0.1:8000  ->  /be/
python tools/serve.py --cc=JP   # bare "/" lands on /jp/
```

`netlify dev` is authoritative — it runs the real edge functions and the
real redirect rules. `serve.py` mimics the routing and stubs `/api/rates`,
but knows nothing about `_headers` or the `Country` conditions.

See `tools/TESTING.md` for what to check.

## Secrets

`DEEPL_API_KEY` goes in `.env`, which is gitignored. Nothing else in this
repo needs a key.
