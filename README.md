# DRP BuildLab — site

Static marketing site. No build step on deploy: Netlify publishes the
repository root as-is.

## Layout

```
src/                    the four pages, in Dutch — EDIT THESE
  index.html
  over-ons/index.html
  prijzen/index.html
  contact/index.html

be/  nl/  fr/  …            GENERATED, one directory per market — do not edit
                        17 of them: be nl fr lu ch de at es gb ie us ca mx id jp sg au

assets/                 css, js, translations, images
  styles.css
  app.js                UI behaviour and language application
  locale.js             market resolution and currency conversion
  i18n.js               all 7 languages
  markets.js            the market table — market -> language + currency
  icons/                favicon.svg, icon-192, icon-512
  img/

netlify/edge-functions/
  rates.js              /api/rates — EUR rates, cached an hour
  geo.js                /api/geo — country lookup (no longer used by the page)
  chat.js               /api/chat — AI chat widget backend (streaming SSE)

tools/
  build-locales.js      regenerates the market directories + sitemap
  translate.js          drafts machine translations via DeepL
  serve.py              local preview server
  TESTING.md            how to test the localisation

404.html                served directly, not generated
_headers                cache and security headers
_redirects              market routing, geo root redirect, legacy URLs
netlify.toml            publish directory only
robots.txt              must live at the web root
sitemap.xml             generated by build-locales.js
site.webmanifest
favicon.ico             stays at root — browsers probe this path
apple-touch-icon.png    stays at root — iOS convention
```

## The one rule

**Edit `src/`, never a market directory.** The 17 market
directories are output. Anything you change in `gb/` is gone the next time
the generator runs:

```powershell
npm run build          # both stages, in order
```

Two stages, and the order matters:

1. **`tools/build-locales.js` — structure.** Rewrites every market directory
   from `src/`: URLs, canonical, hreflang, market-prefixed links, the market
   picker, and the social tags in that market's language. Also regenerates
   `sitemap.xml`.
2. **`tools/prerender.js` — text.** Loads each generated page in headless
   Chromium, lets the real `applyLang` translate it, and writes the result
   back. This is what puts the translated copy *in the HTML* rather than
   applying it after load.

Stage 1 overwrites everything stage 2 did, so never run it alone unless you
mean to drop back to untranslated HTML. `npm run build` runs both.

Prerendering needs Chromium:

```powershell
npm install
npx playwright install chromium     # once, if you have none
```

Run after editing a page in `src/`, changing a translation, or adding a
market to `assets/markets.js`.

### Why prerender

Before it, every market page shipped Dutch body text under a `<html lang>`
claiming otherwise -- `/jp/` told crawlers it was Japanese and handed them
"Jouw bedrijf". The pages were indexable in structure but not in content.

Prices are deliberately **not** prerendered: they stay in EUR in the HTML and
convert client-side from live rates. Baking a converted figure would freeze
one moment's exchange rate into a static file.

The generated output is committed rather than built on Netlify. A build
command is one more thing that can fail on deploy — this site has already
lost an afternoon to a `netlify.toml` change — and generated files in git
show up in a diff.

## Markets

A market is a URL segment carrying **both** a language and a currency, the
way nike.com/gb/ and nike.com/mx/ do. That separation is the point: `/gb/`
and `/us/` are both English at different currencies, `/es/` and `/mx/`
both Spanish at different currencies.

17 markets, 7 languages, 10 currencies. Defined once in
`assets/markets.js` and read by both the page and the generator.

Adding one is a line in that file plus a rerun of the generator, then a
`Country` rule in `_redirects` so a bare `/` from that country lands there.

## Local preview

```powershell
python tools/serve.py           # http://127.0.0.1:8000  ->  /be/
python tools/serve.py --cc=JP   # bare "/" lands on /jp/
```

`netlify dev` is authoritative — it runs the real edge functions and the
real redirect rules. `serve.py` mimics the routing and stubs `/api/rates`,
but knows nothing about `_headers` or the `Country` conditions.

See `tools/TESTING.md` for what to check.

## AI Chat Widget

A floating chat button appears on every page. It calls `POST /api/chat`, which
is handled by `netlify/edge-functions/chat.js`.

**How it works:**
- The edge function reads `data/pricing-catalog.json` and builds a system prompt
  from it (services, prices, what we don't do, process info).
- It calls the Anthropic API (`claude-sonnet-4-6`) with streaming and forwards
  the response as Server-Sent Events to the browser.
- Rate limiting: max 20 messages per IP per 10 minutes (in-memory, per edge isolate).

**To update prices or services:** edit `data/pricing-catalog.json` only. That
file is the single source of truth — the chat widget reads it at runtime.

**Required environment variable:** `ANTHROPIC_API_KEY`
Set it in Netlify → Site configuration → Environment variables.
Never commit the real key; `.env.example` shows the expected name.

**Frontend:** `assets/chat.js` injects the widget DOM and handles streaming.
`src/css/47-chat.css` contains all widget styles (compiled into `assets/styles.css`
by the build tool along with the rest of the CSS).

## Blog

Articles are Markdown files in `content/blog/`, usually committed by the team
CMS at cms.drpbuildlab.com (repo drp_cms). `tools/concept/build.js` turns them
into `/blog/` and `/blog/<slug>/` (via `tools/concept/blog.js`), and
`localize.js` publishes each article only in the languages it lists. The
format and its rules are in [content/blog/README.md](content/blog/README.md).

A push that touches `content/blog/` on `main` runs
`.github/workflows/blog.yml`: the same build and localize steps as a local
release, then a commit of `concept/` and the translation cache. Netlify deploys
that commit as usual.

Under each article:

- **Share links:** WhatsApp, X, Instagram, and copy link. Instagram has no share link, so on a phone it opens the system share sheet; elsewhere it copies the URL.
- **Like and comment, with no account:**
  - Both go through `netlify/edge-functions/blog.js` (`/api/blog`) to the CMS's Neon database, using the restricted `blog_site` role.
  - A like is remembered by a random id in localStorage, created only when someone presses Like. No cookie is set, and no IP or email is stored.
  - Comments appear only after someone approves them at cms.drpbuildlab.com/comments.
  - Without `BLOG_DATABASE_URL` the like button and comments stay hidden.

Every article page also carries `<meta name="drp-rev">` (the git hash of its `.md`). The CMS uses it to show the editor when their article is live.

## Secrets

`DEEPL_API_KEY` goes in `.env`, which is gitignored.
`ANTHROPIC_API_KEY` goes in Netlify's environment variables UI, not in any file.
For the blog workflow, `DEEPL_API_KEY` also goes in GitHub → Settings → Secrets
and variables → Actions. Without it the workflow still runs, but new text stays
in English.

For blog likes and comments, add these in Netlify's environment variables:

- `BLOG_DATABASE_URL` (required): the `blog_site` connection string. Never use the database owner's.
- `RESEND_API_KEY`, `MAIL_FROM` and `ADMIN_EMAIL` (optional): the same values form.js already uses. With them, the team gets an email when a comment is waiting.
